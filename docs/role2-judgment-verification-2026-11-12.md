## 가이드 체크리스트 대조

1. JS 판정 엔진의 웹 연결 확인 — 확인됨.
   `web/app.mjs`가 `judgeContest(contest, {...profile, selectedSectionId}, settings)`를
   호출하고, `settings`는 `{ confidenceThreshold: 0.7 }`이다. 서버 판정 API는 없으며
   판정은 100% 브라우저에서 동작한다.
2. 모호한 조건·부문별 제한·근거 누락 재현 — 확인됨.
   - 부문별 제한: KISTI 경진대회는 문제발굴 부문 `needs_review`(정규화되지 않은 추가 조건),
     문제해결 부문 `eligible`로 갈려 공고 전체가 `section_divergence`로 확인 필요가 된다.
   - 정규화되지 않은 조건: 데이터+AI 챌린지의 `other_conditions`가 `unmodeled_condition`으로
     확인 필요가 된다.
   - 근거 누락: 조건이 명시됐는데 프로필 값이 없으면 `missing_profile`로 확인 필요가 된다
     (빈 프로필 22건이 전부 이 경로 또는 `unmodeled_condition`이다).
   - 단, `ambiguous_enumeration`·`low_confidence`·`unmapped_evidence` 경로는 seed 실데이터에
     해당 사례가 없어 합성 테스트로만 커버된다(아래 공백 참조).
3. 미검증 공고의 '지원 가능' 표시 검토 — 검토 완료, 엔진 변경 없음.
   `validation_status: "unverified"`인 샘플도 명시된 조건을 충족하면 `eligible`이 된다.
   이는 엔진이 자격 조건만을 판정하고 검수 상태 표시는 프론트가
   `is_sample`/`validation_status`로 분리해 담당하는 설계다. 엔진 차원의 게이트는
   `validation_status: "draft"`에만 적용된다. 기존 테스트도 `unverified` 공고의
   `eligible`을 기대하므로, 동작을 바꾸지 않고 구분 방식을 문서로 확정한다.
4. 근거 없는 판단의 '확인 필요' 처리 — 확인됨 (합성 테스트).
   - 근거 없이 연령 조건에 불충족하는 합성 공고는 `needs_review`(`age:unclear_evidence`)가 된다.
   - 같은 조건에 본문 근거를 붙이면 `ineligible`(`age:mismatch`)이 된다.
   - seed 실데이터에서는 `unclear_evidence` 사례가 0건이다. 모든 불충족 판정이 본문 근거를
     갖고 있어 격하 경로가 발동하지 않았다.
5. 입력 프로필과 판정 응답 예시 공유 — 본 문서와 `docs/role2-judgment-contract.md`로 공유한다.
   테스트 보완: 기존 JS 테스트 19건이 전부 통과하고 엔진 변경이 없어 신규 회귀 케이스를
   추가하지 않았다.

## draft 게이트 확인

- 실제 검수 전 초안 2건(아래 대조 참조)은 부문별 판정과 무관하게 공고 전체가
  `needs_review`(`source:unverified_import`)가 된다. 용산 초안은 부문 판정이
  `eligible`인데도 게이트가 적용됨을 확인했다.
- 합성 공고로도 확인했다. 조건이 없는 공고는 `draft`일 때 `needs_review`,
  `verified`일 때 `eligible`이다.

## 잘못된 '지원 가능' 판정 여부

발견하지 못했다. 다만 조건·근거가 전무한 8건은 빈 프로필에서도 `eligible`이 된다.
엔진 규칙 오류가 아니라 데이터 공백이다. 명시된 조건이 하나도 없으면 엔진이 확인할
대상이 없어 `matched`가 되기 때문이다. 해당 8건:

- 2026년 서울특별시 어린이·청소년 시민발언대 「청소년이 바꾸는 서울」 인스타툰 공모전
- 2026년 멘토링 수기공모전 (유의사항 성격의 `other_conditions` 1건은 권고 조건으로 제외됨)
- 실손24 영상 공모전
- LOTTE AX CHALLENGE 2026
- 2026 제18회 전국청소년 모형항공기대회
- 제39회 무등일보 신춘문예
- [F&S] ₩50,000 LOOK
- 2026년 지역문제해결 아이디어 발굴 부여 솔버톤 대회

실제 공고가 들어올 때는 조건 추출이 비어 있는 공고를 검수 단계에서 걸러야 한다.
이는 추출·검수 영역의 일이며, 엔진이 조건 없음을 `확인 필요`로 바꾸는 변경은
기존 동작과 테스트를 깨므로 하지 않았다.

## 데이터 커버리지 공백 (실데이터 기준)

- `region`·`major_scope`가 명시된 부문이 31개 부문 중 0건이다. 지역·전공 조건 경로는
  실데이터로 한 번도 동작 확인이 안 됐다.
- `confidence` 값이 전 부문 전 필드에서 비어 있다. `low_confidence` 경로가 실데이터에서
  발동할 수 없는 상태다.
- `category`는 30건 전부 null, `topic_tags`·`skill_signals`은 전부 비어 있다.
  (관련성 엔진의 입력 공백이며, 자격 판정에는 영향이 없다.)

## 결론과 남은 일

- 엔진 본체는 보수적 설계대로 동작하며, 잘못된 '지원 가능' 판정은 발견하지 못했다.
- 남은 역할 2 작업은 엔진 구현이 아니라 실제 데이터 대조·검증이다.
  - 정확도 검증: 검수 완료 실제 공고와 수기 정답이 0건이라 아직 측정할 수 없다.
    실제 공고가 들어오면 프로필별 기대 판정을 정하고 엔진 결과와 비교한다.
  - 판정 오류 수정: 역할 4의 오류 리포트가 0건이라 착수할 재료가 없다.
    리포트가 오면 회귀 케이스를 먼저 추가한 뒤 규칙을 수정한다.
  - 판정 기능의 서버 연결: 팀 결정 사항이다. 서버 판정을 원하면 판정 API 계약
    설계부터 필요하고, 아니면 브라우저 판정 유지를 명시적으로 확정한다.
- Python `eligibility.py`를 별도 판정기로 재구축하지 않는다(가이드 경계).
  실제 판정 코드는 `web/decision-engine.mjs` 하나다.
