# 데이터 공급원과 팀 작업 경계

2026-11-07 공식 제공 페이지 확인 기준. 공모전과 학과는 서로 다른 데이터다. 학과 API를 호출해도 공모전 목록이나 개인의 참가 자격이 나오지 않는다.

## 공식 데이터 후보

| 목적 | 출처 | 사용할 값 | 범위와 한계 |
| --- | --- | --- | --- |
| 전국 학교·학과 입력 보조 | [한국대학교육협의회 전국대학별학과정보표준데이터](https://www.data.go.kr/data/15107737/standard.do) | `SCHL_NM`, `SCSBJT_NM`, `CTPV_NM`, `UNIV_ONESLF_AFIL_NM`, `YR`, `SCSBJT_STTS_NM` | 전국 단위로 병합되지만 시차가 있다. 학과명 입력 보조일 뿐 재학·공모전 자격 증빙은 아니다. |
| 전공 계열·설명 보강 | [커리어넷 학과정보 API](https://www.career.go.kr/cnet/front/openapi/openApiMajorCenter.do) | `svcCode=MAJOR`, `searchTitle`, `majorSeq`, 학과 설명 | 별도 승인 키가 필요하다. 학과 사전 성격이며 학교별 개설 현황의 완전한 대체재로 취급하지 않는다. |
| 일부 공공 지원사업 후보 | [한국콘텐츠진흥원 지원사업공고](https://www.data.go.kr/data/15134251/openapi.do) 등 기관별 API | 공고 제목·원문 주소·기간이 실제 응답에 있는 경우에만 후보로 저장 | 지원사업·모집공고가 섞여 있으므로 공모전 여부와 개인 참가 자격을 원문으로 다시 확인해야 한다. |
| 시연용 실제 공모전 | 주최 기관 공식 공고 | 제목, 부문별 자격, 짧은 근거, 원문 링크, 확인 시각 | 주최 기관마다 형식이 다르다. 1건씩 검수해 `curated.json`에 등록한다. |

전국의 모든 학과가 참가할 수 있는 모든 공모전을 보장하는 단일 공식 API는 확인하지 못했다. 학과 카탈로그는 사용자 입력을 돕고, 공모전 공급은 별도의 공식 주최처·기관 API별로 검증해야 한다. **현재 서비스에 실제 공고가 등록되기 전에는 전국 공모전 검색으로 홍보하지 않는다.**

### 학과 API 호출 계약

- 주소: `https://api.data.go.kr/openapi/tn_pubr_public_univ_major_api`
- 요청: `serviceKey`, `pageNo`, `numOfRows`(최대 1000), `type=json`, 확인한 공시연도의 `YR`
- 실행: `python -m posting_validation.departments --year <공시연도>`
- 출력: `web/data/departments.json`에 학교·학과·지역·계열과 출처·동기화 시각만 저장한다. 모든 페이지를 받지 못하면 기존 파일을 보존한다.
- 운영자가 키를 환경변수 `DATA_GO_KR_SERVICE_KEY`로 제공한다. 키를 소스·브라우저·커밋에 넣지 않는다.

화면은 `GET /api/schools?q=...`로 대학명을 제안한다. 현재 이 경로는 동기화된 학과 카탈로그에서 중복 학교명을 제거해 검색한다. 저장소에 Elasticsearch 연결이나 인덱스는 없으며, DB 담당자가 검색엔진을 도입하면 같은 응답 형태(`schools: [{name, region}]`, `count`, `reference_year`)를 유지해 검색 구현을 교체할 수 있다. 공식 자료 동기화 전에는 결과가 비어 있고 학교명 직접 입력이 가능하다.

## 세 담당자에게 넘길 계약

| 담당 | 먼저 구현할 일 | 인수 기준 |
| --- | --- | --- |
| DB·데이터 | 공식 학과 동기화 실행과 갱신 시점 기록, 공고 URL 중복 제거, `curated.json`의 부문·근거·주제·역량 신호를 데이터 모델로 이전할 설계 | 출처별 건수·검수 상태를 확인할 수 있고 기존 `seed.json` 경로가 유지됨 |
| UI/UX | 학과 자유 입력과 검색 제안, 자격 배지와 주제 관련성 설명의 분리, 실제·샘플·검수 전 표시, 모바일 과제 흐름 | 사용자가 ‘관련성 높음’을 ‘지원 가능’으로 혼동하지 않고 원문 근거를 찾을 수 있음 |
| 기능 고도화·정규화 | 공식 원문의 부문별 조건, 주제 태그, **명시된** 역량 문장과 근거를 검수하는 규칙; 공급원별 응답을 공통 스키마로 변환 | 근거 없는 역량을 만들지 않고 모호한 자격은 ‘확인 필요’; 회귀 테스트와 120건 수기 정답 리포트 통과 |

API에서 받은 공고 메타데이터는 후보일 뿐이다. 원문에 없는 전공·역량·참가 자격을 채우지 않는다. `skill_signals`의 `evidence`는 원문에서 확인한 짧은 발췌로 제한한다. 수집 시각, 출처 URL, 생성 명령을 데이터 변경 PR에 기록한다.
